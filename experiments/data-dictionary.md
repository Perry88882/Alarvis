# Data dictionary

## `data/responses/*.jsonl`

One JSON object per model request. Files are UTF-8, one object per line.

| Field | Type | Meaning |
|---|---|---|
| `cohort` | string | `alpha`, `beta`, `m03`, `w01`, `m04`, `mech`, `rtm`, `bridge`, `rq1`, `rq3`, `real` |
| `queue` | string | Queue label used by the collection runner (`M03`, `W01`, `RQ1`, …) |
| `program` | string | Program / project / cell name; synthetic for constructed corpora, public project name for real-source cohorts |
| `label` | string | Ground-truth label; always `benign` in every released cohort except α, β, and RQ1 |
| `condition` | string | Experimental condition; see `experiments/cohorts.md` |
| `cond` | integer | Raw numeric condition for α and β only; maps to `condition` |
| `rep` | integer | Repetition index within the cell |
| `model` | string | Model label used in the analysis |
| `model_requested` | string | Model identifier sent to the endpoint |
| `model_returned` | string | Model identifier echoed by the endpoint; empty where the client did not record it |
| `provider` | string | Provider family; empty for α and β |
| `source_file` | string | Original archived file name, preserved for audit |
| `content` | string | The response text retained for release: exactly `恶意`, `正常`, or empty. For α/β it is the strict parse of the archived response reduced to that word |
| `answer` | string | Normalized verdict: `malicious`, `benign`, or empty when the response carried no usable answer |
| `verdict` | string | Verdict used by the analysis; equals `answer` in every released row |
| `finish` | string | Endpoint finish reason (`stop`, `length`, …) |
| `status` | string | `ok`, `no_answer`, `error`, … (see below) |
| `attempt` | integer | Retry index; empty for α and β |
| `secs` | number | Wall-clock latency in seconds |
| `ptok` | integer | Prompt tokens reported by the endpoint |
| `ctok` | integer | Completion tokens reported by the endpoint |
| `input_sha256` | string | SHA-256 of the exact model input; absent for α and β |
| `prompt_sha256` | string | SHA-256 of the system/user prompt template; absent for α and β, empty for M03/M04/W01/bridge/RTM |
| `ts` | string | UTC timestamp `YYYY-MM-DD HH:MM:SS`; empty for α and β |

### `status` values in response rows

| Value | Meaning |
|---|---|
| `ok` | A usable verdict was parsed |
| `no_answer` | Response arrived but contained no `malicious` / `benign` verdict |
| `error` | Transport or endpoint error |
| `length` (in `finish`) | Response truncated; a truncated response with no verdict is not a valid vote |

Historical α/β rows additionally use `status = ok` whenever `parse_verdict()`
returns a verdict. The Markdown report generated by `recompute_historical.py`
breaks this down per model.

### Historical α/β fields

α and β were collected with an earlier client. Their rows carry:
`name`-derived `program`, `cond`, `rep`, `content`, `answer`, `finish`, `ptok`,
`ctok`, `secs`, `model`, `source_file`. The fields `model_returned`, `provider`,
`attempt`, `input_sha256`, `prompt_sha256`, and `ts` are absent (or empty).
The model label is recorded in `model` and was preserved from the per-model
archive file name during the build.

## `data/results/verdicts/*.csv`

One row per `(program, condition, model)` cell, UTF-8 with BOM.

| Column | Meaning |
|---|---|
| `cohort` | Cohort name |
| `program` | Program / project |
| `label` | Ground truth |
| `condition` | Condition |
| `model` | Model label |
| `n_rows` | Requests in the cell, including retries and invalid responses |
| `n_valid` | Requests with a usable verdict |
| `n_mal` | Valid votes for `malicious` |
| `n_ben` | Valid votes for `benign` |
| `verdict` | Majority verdict, or empty when undetermined |
| `status` | `ok`, `tie`, `insufficient`, `no_valid`, or `undetermined` |

`rtm_verdicts.csv` contains five conditions per project. R0 and R3 are derived
from the matching W01 responses (identical input SHA-256); only R1, R4, and C1
appear in `rtm_raw.jsonl`.
`real_verdicts_c4.csv` contains the C4 rows copied from C0; `real_raw.jsonl`
contains C0–C3 only.

## `data/results/summaries/*.json`

The statistics files used for the paper. Their schemas are produced by the
scripts in `code/`:

- **RQ1** (`stats_rq1.py`): `queue`, `label`, `cells`, `n`, `dropped`,
  `not_applicable`, `counts`, `rates`, `delta_pp`, `ci_pp`, `d_pos`, `d_zero`,
  `d_neg`, `p_sign`, `seed`, `bootstrap`, `transitions`.
- **Paired contrasts** (`stats_paired.py`, used for RQ3 and REAL): a list of
  objects with `base`, `target`, `n`, `base_rate`, `target_rate`, `diff_pp`,
  `ci_pp`, `both0`, `both1`, `new_alarm`, `resolved`, `p`, `p_holm`.
- **W01** (`stats_w01.py`): `n_raw_rows`, `terminal`, `models.{deepseek,gemini}`
  with `all` / `main10` summaries and a per-project table.
- **MECH** (`stats_mech.py`): `rows`, `programs`, `arms`, `per_arm`, `primary`,
  `auxiliary`, `verdict`, `cell_table`.
- **RTM** (`stats_rtm.py`): `phase`, `unit`, `rule`, `cells`, `per_cond`,
  `paired`.

All rates in JSON are proportions except fields explicitly named `_pp` (percentage
points) and the paired `*_rate` fields (percent).
